# Scenario authoring rules

- Scenario ids are stable public evidence identities once used in hosted evidence.
- Fixture generation must be deterministic and bounded.
- Network-backed public data is not a canonical fixture; commit or deterministically generate reference inputs.
- Declare semantic observation categories separately from runtime phases.
- A renderer diagnostic may be evidence but never semantic truth.
- Required capability absence is unavailable, not success.
- Do not encode Moonlight thresholds or release policy in scenario files.
- Do not copy runtime-profiler's evidence-bundle schema into this repository.
- Extend existing workload families before creating new scenario ids.
- Reference adapters normalize observations; they do not make MapLibre or Leaflet architectural dependencies.
